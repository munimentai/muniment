### Durable local run journal
- DECIDED — ADR 0002 makes a per-run append-only SQLite event journal authoritative; external effects are never silently re-executed and large bodies live in CAS.
- DONE — schema/envelope/atomic append, reducer/replay, Pi translation, deletion/collection/retention, deterministic export, crash-safe compaction, cursor-paginated run summaries, and authorized Linux companion `thread.list`/`thread.open` backed by redacted projections.
- RULE 2026-07-12 — Pre-launch schema work on the desktop's local journal is in scope for this lane. The owner's post-go-live restriction applies to the muniment-cloud deploy path, not this repository.
- OBSERVED 2026-07-28 (planner measurement, database lens) — `events_run_order` on `events(run_id, run_seq)` duplicates the index that `UNIQUE(run_id, run_seq)` already creates on the same columns in the same order. On a replica `events` table holding 160,000 rows, dropping it cut the file from 91.6 MB to 88.4 MB, and `EXPLAIN QUERY PLAN` for the run-ordered read still reported `SEARCH events USING INDEX sqlite_autoindex_events_2 (run_id=?)`. `events` is the fastest-growing table, so every append pays for a second identical b-tree entry. DONE 2026-07-28 — that drop landed (MUNIDESK-589) as a schema-v4 migration step. `thread_events_thread_order` and `run_threads_thread_run` duplicate their own UNIQUE constraints the same way, and they stay parked because `validate_thread_schema` asserts their exact SQL and two corruption tests tamper with them.
- Compaction copies the schema with `VACUUM INTO`, so an index change needs no compaction work.
- MEASURED 2026-07-31 (planner, read every SQLite call site in `src-tauri/core/src/journal/`, database lens) — app launch reads the whole journal twice, and both reads grow without bound. `validate_database` (`src-tauri/core/src/journal/mod.rs:2013`) runs `SELECT ... FROM events ORDER BY run_id,run_seq` with no `WHERE` and no `LIMIT`, deserializes each row, and re-serializes it through `canonical_envelope` to compare bytes. It then scans `thread_events` the same way and runs five more unbounded aggregates. `RunJournal::open` calls it unconditionally (`mod.rs:672`), and `ChatState::new` opens the journal once per launch (`src-tauri/src/chat.rs:539`). `reconcile_interrupted_runs` (`src/chat.rs:585`) then calls `run_event_types` (`mod.rs:1198`), a second unbounded ordered read of every event ever recorded, and issues one further query per non-terminal run. A journal holding 50,000 events therefore pays 50,000 JSON parses plus 50,000 re-serializations before the first frame, every launch, forever.
- NOT SELECTED 2026-07-31 (planner) — that pair needs a design call before it needs a ticket. `validate_database` exists to catch a tampered or corrupted journal, so bounding its scan weakens the guarantee it provides. The candidates are a bounded newest-events check at open with the full pass moved off the launch path, a full pass on a schedule, and a stored high-water mark that records how far validation has already reached. Naming one is the next slice, and it is a decision rather than a query rewrite.
- MEASURED 2026-07-31 (planner, read the open path again) — the launch cost is larger than that note records. `validate_database` opens with `PRAGMA integrity_check` (`src-tauri/core/src/journal/mod.rs:2007`), which walks every page of the file before the envelope pass starts. `RunJournal::open` (`mod.rs:638`) calls that function at `mod.rs:672` on every open. A launch therefore pays a full structural check, a full envelope re-serialization pass, and then the separate `run_event_types` read. ADR 0002 states the current rule in one sentence: "On open, SQLite integrity and envelope/sequence validation precede replay." SQLite documents `PRAGMA quick_check` as the cheaper structural check, and published operating guidance keeps a full integrity check off the interactive path.
- SELECTED 2026-07-31 (this wave) — that decision, as a dated amendment inside ADR 0002. The amendment names the launch-path read policy for the open-time check and for the interrupted-run reconcile. It states the guarantee each answer keeps and the one it drops, states when the full pass runs, states whether a schema step follows, and names the first implementation slice. It writes no runtime code.
- DONE 2026-07-31 — that amendment landed (MUNIDESK-720). On open the desktop runs `PRAGMA quick_check`. It then validates the 256 highest-`append_ordinal` envelopes in `events` and the 256 highest in `thread_events`. It also reads each represented stream's boundary predecessor. The amendment states what those bounded checks still catch and what they no longer catch. The full integrity, envelope, sequence, schema, identity, and aggregate pass runs after the first frame, and the desktop gates every external effect until it succeeds. `reconcile_interrupted_runs` reads candidate run IDs from a transactionally maintained recovery-state projection instead of reading every event type. Planner read 2026-07-31 confirmed the corruption response, the preserved fail-open classification, and the two named implementation slices.

### ACP interop, and the retired first-party editor extension (owner ruling 2026-07-29)
- OWNER RULING 2026-07-29 — muniment takes the ACP agent direction. muniment exposes the Agent Client Protocol, so any ACP editor drives the muniment runtime. The completed E2 first-party editor extension is RETIRED. The muniment CLI surface is DEFERRED indefinitely under the same ruling. An ADR records the direction before any ACP code.
- MEASURED 2026-07-29 (planner, web research against the protocol site and the package registries) — the owner's facts hold, and three of them change the shape of the decision. ACP is Apache-2.0 and speaks newline-delimited JSON-RPC 2.0 over stdio. The CLIENT spawns the AGENT as a subprocess, so an ACP editor starts a muniment process rather than connecting to one. Protocol version 1 is stable and negotiates as one integer in `initialize`. The v2 schema draft published 2026-07-20 states that its wire protocol may change incompatibly in any SDK release. The Rust crate `agent-client-protocol` published 2.0.0 on 2026-07-23 with MSRV 1.88.0, and `@agentclientprotocol/sdk` published 1.3.0 on 2026-07-21 with zero runtime dependencies. Both SDKs now live outside the protocol monorepo, in `agentclientprotocol/rust-sdk` and `agentclientprotocol/typescript-sdk`, so a dependency pin names the SDK repository rather than the spec repository.
- CONSTRAINT 2026-07-29 (planner) — ACP inverts two of this repository's ownership rules, so the ADR must answer both. First, the editor spawns the agent, while ADR 0012 makes the per-user runtime service the single owner of runtime state, so the spawned process cannot become a second executor. Second, ACP hands filesystem and terminal capability to the CLIENT: the agent calls `fs/read_text_file`, `fs/write_text_file`, and `terminal/*` back into the editor, and it asks the editor for permission through `session/request_permission` with the four option kinds `allow_once`, `allow_always`, `reject_once`, and `reject_always`. muniment owns filesystem access, tool execution, and the authoritative journal, and `chat_answer_permission` plus the `permission.requested` and `permission.resolved` events are how a native gate resolves. The ADR must state whether a gate answered inside a third-party editor satisfies a muniment grant check, and what the receipt records when it does. The protocol documents cancellation for a pending permission request and documents no timeout.
- SEQUENCED 2026-07-29 — the document splits in two, the way ADR 0020 did. Ownership, session identity, governance, the wire subset, capability negotiation, the version stance, and the dependency pins are more decisions than one reviewable ticket carries. Slice 1 decides who speaks ACP and how an ACP session stays governed, including the composition with ADR 0009, ADR 0011, and ADR 0012, and the disposition of the `editor-extension/` directory. Slice 2 decides the supported v1 method subset, the capability answers for `fs` and `terminal`, the v1-versus-v2-draft stance, the pinned SDK versions, and which editors the release claims. Slice 1 carries the governance statement, because governance is what lets an ACP session exist at all. ADR 0021 is reserved for the open on-device classifier store ADR, so the ACP document takes 0022.
